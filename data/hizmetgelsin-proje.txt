HizmetGelsin (Berbergelsin) — Hizmet Sağlayıcı Eşleştirme Uygulaması

Proje özeti: Müşterileri yakınlarındaki mobil hizmet sağlayıcılarla (örneğin berberler) eşleştiren, Flutter tabanlı mobil uygulama ve ASP.NET Core tabanlı backend'den oluşan tam kapsamlı bir uygulama.

Frontend teknolojileri: Flutter 3.44.4 (Dart 3.12.2). State management için BLoC/Cubit deseni kullanıldı, oturum kalıcılığı için hydrated_bloc kullanıldı. Yönlendirme (routing) için go_router kullanıldı — bu, oturum durumuna göre otomatik yönlendirme yapabilen gelişmiş bir router. Ağ istekleri için dio kütüphanesi, token yenileme işlemleri interceptor mimarisiyle otomatikleştirildi. Harita ve konum için flutter_map, geolocator ve Google Places API kullanıldı. Gerçek zamanlı iletişim için signalr_netcore, güvenli veri saklama için flutter_secure_storage kullanıldı.

Backend teknolojileri: .NET 8.0/9.0, ASP.NET Core Web API (Controller mimarisi). Veritabanı olarak PostgreSQL, konum/harita verileri için PostGIS eklentisi (NetTopologySuite üzerinden) kullanıldı. ORM olarak Entity Framework Core kullanıldı. Kimlik doğrulama JWT Bearer token ile yapılıyor, TokenVersion alanı sayesinde oturumların uzaktan iptal edilebilmesi (session revocation) destekleniyor. Gerçek zamanlı bildirimler için SignalR Hub kullanıldı. IP veya kullanıcı ID bazlı rate limiting (istek sınırlama) mekanizması var.

Kullanıcı rolleri: Müşteri (hizmet arayan), Berber/İşletme (hizmet sunan, onboarding sonrası onay bekleyen), Admin (yönetici paneli).

Kimlik doğrulama akışları: Hem telefon/OTP girişi hem Google ile giriş destekleniyor. OTP akışı AuthCubit üzerinden yönetiliyor: sendOtp → verifyOtp → token'lar flutter_secure_storage'a kaydedilir. Google girişinde idToken backend'e gönderilip doğrulanıyor. Oturum yenileme (refresh) sırasında birden fazla eşzamanlı 401 hatası gelirse, "single flight" deseniyle (Completer kullanılarak) yalnızca bir refresh isteği yapılıp diğerleri onu bekletiliyor — böylece gereksiz çoklu refresh istekleri engelleniyor.

Teknik/mimari kararlar: Güvenlik için AsNoTracking kullanılarak veritabanı sorgularında gereksiz değişiklik takibi engellendi. Rate limiting hem IP hem kullanıcı bazlı çalışıyor. Talep ve teklif sisteminde idempotency (aynı isteğin yanlışlıkla iki kez işlenmesini önleme) kontrolü var. Değerlendirme (rating) sisteminde 7 günlük düzenleme penceresi ve yorum bildirme (report) özelliği bulunuyor.

Yayınlama süreci: Proje GitHub'a portföy amaçlı yayınlanırken, git geçmişinde bulunan hardcoded (koda gömülü) kimlik bilgileri temizlendi, Android keystore'u yeniden oluşturuldu (rotate edildi), git geçmişi temiz bir commit'e sıfırlandı ve iki dilli (Türkçe/İngilizce) bir README hazırlandı.
